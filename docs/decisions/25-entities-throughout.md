# Entities throughout, each with its own vitality

What a person runs into in the world stands for the code's entities, and
how things connect stands for the dependencies between them. A landmark
stands for an entity, as a building does, and Jev decides which entities
become landmarks and which become buildings; prominence suggests a
landmark, but nothing fixes how many of either, or ties a landmark to a
file or a region. A trail stands for a dependency between two entities,
and the `link` kind reads both entities' facts.

Vitality belongs to each file and each entity and shows on everything that
stands for it, never as one value for the whole world. A trail's wear
follows the vitality of the two entities it joins, blending along it from
one end to the other: a trail between thriving entities is worn bare, and
one to a failing entity grows over and fades. It changes live, with
nothing rebaked.

## Why

The reviewer, on trail wear averaged over the world: "Vitality is not just
the world!! It exists by file and by entity!!!" On landmarks: "I don't think
you need to be prescriptive with one land mark per file. This represents a
world. Entities are spread across in different ways." They chose "Entities
throughout": landmarks and trails stand for entities.
